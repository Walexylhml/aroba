# ÀRỌBA — Yoruba History & Heroes

ÀRỌBA ("Father of Stories") is a responsive web app telling the story of Yoruba history and heroes. Live: https://lively-pasca-269d31.netlify.app/

## What this repo is

This repo is the single, self-contained home for Aroba's story data. The three original Google Docs were only ever working drafts; once `data/stories.json` is built (see `BUILD.md`), those docs are no longer needed and can be retired.

## Data model

Each story record has these fields:

- `id` — stable slug, e.g. `itan-oba-fall-of-owu`
- `title_en` — English title
- `title_yo` — Yoruba title (where available)
- `category` — one of the 9 canonical categories (see below)
- `secondary_tags` — array of cross-cutting tags
- `summary` — one or two sentence precis
- `canonical_source` — which doc holds the richest telling (COLLECTION | CONSOLIDATED | CONTD)
- `source_anchor` — the exact heading to locate the body in the exported text
- `consolidates` — array of superseded/duplicate drafts folded into this record
- `status` — `canonical` | `superseded` | `merged`
- `body` — filled in at build time from the one-time doc export (see BUILD.md)

## The 9 categories

1. Ìtàn Ọba — Histories & Kings
2. Ológun / Kakanfo — Warlords
3. Ìtàn Ẹrú — Slave Trade
4. Diaspora
5. Òrìṣà — Divinities
6. Ìwé / Ìtàn Àpagbè — Folktales & Literary
7. Great Yoruba Women
8. Living Legends
9. Nigeria History

## Repo layout

- `data/manifest/*.json` — one manifest file per category. Holds all dedup and re-categorization decisions (every merge, drop, and re-home is recorded). This is the curated brain of the project.
- `BUILD.md` — the one-time step to export story bodies from the Google Docs and merge them into `data/stories.json`.
- `data/stories.json` — the final, self-contained output (bodies + metadata) the app points to. Generated by the build step.

## How to rebuild

See `BUILD.md`. In short: export the 3 docs to plain text once, run the tiny merge that matches each manifest `source_anchor` to its body, and write `data/stories.json`. After that the docs can be archived.
